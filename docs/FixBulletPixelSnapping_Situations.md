# 子弹亚像素绘制的现状

本文件只记录一件事：各作把「不旋转的精灵」量化到整像素的位置在哪、是否需要修复、修复用了什么办法。
随排查进展更新；`docs/interpolation.md` 是需求原文，不在这里重复。

th11–th19 的块入口都是 `test ..., 1` + `jz`，即只有 `drawFlags & 1` 的路径取整、旋转路径本来就不取整，
与 th07 / th08 的形状一致。

**但只 NOP 那四条 `frndint` 不够，th11 上已经证过**：补丁打进去、`0x44F92A` 确实变成 `90 90`，画面
毫无变化。量化在上一层，`sub_4500B0` 先调 `sub_44FE30` 算四个顶点，再调 `sub_44F880`；`sub_44FE30` 对
左边界和上边界各调一次 `sub_4520C0`，那是 `floor` 的包装（`fld 参数` → `call _floor` → 返回）。等四条
`frndint` 执行时顶点已经是整数。

所以判断某作「有没有第二层」，要看**顶点是在哪里算出来的**，也就是顺着提交函数的调用者往上追一层，
而不是只看谁调用了那个取整块。th11 的 `sub_44F880` 调用者全都不碰 `floor`，可 `floor` 藏在它的兄弟
函数 `sub_44FE30` 里。**th12–th19 上表里写的「无」都是按旧判据得出的，需要按这个方法复查。**

地址来自 IDA 与 dumpbin 双向核对。th128 的条件是 `test byte ptr [ebp+arg_0], 1`（标志在栈参数上而不是 `bl`），
按字节特征找会漏，要看指令文本。

## 各作的量化点

### th06

`AnmManager::Draw2`，x 一条、y 一条。两条 `frndint` 换 NOP，另给子弹精灵各建一张纹理并把 UV 铺满整张、
地址模式设 `D3DTADDRESS_CLAMP`，越界采样被钳到精灵自己的边缘。

### th07 / th08

`AnmManager::DrawInner` 的 `drawFlags & 1` 分支，四条一组，各跟 `fsub 0.5`。`frndint` 换 NOP，在
`DrawInner` 入口给非子弹补回取整，子弹改用预乘副本 + 透明边框 + 共享打包图集，进出子弹段各切一次 `SRCBLEND`。

### th10

先只把提交函数（`sub_442670`）的四条 `frndint` 换掉，画面完全不变——量化在上一层：`sub_443080` 在算锚点几何时
对「中心减半宽」调了两次 CRT `floor`（x 边 `0x443149`、y 边 `0x443216`）。两处 `call floor` 换成
`fld qword [esp]`（把同一段代码刚压栈的值读回）加两个 NOP，边界就保留小数；四条 `frndint` 一并去掉，覆盖
anchor 1、2 这两条本来就不 floor 的路径。不做副本、不换纹理、不切混合。

### th11

与 th10 同形。量化点是 `sub_44F880` 的四条 `frndint`（`0x44F92A/938/946/954`，`test bl, 1` 控制），
但只 NOP 它们画面不变：顶点由 `sub_44FE30` 算出，它在居中分支里对左边界和上边界各调一次
`sub_4520C0`，而那是 `floor` 的包装（`0x4520D2` 的 `call _floor`，目标 `0x486590`）。两处改法同 th10：
`0x4520D2` 换 `fld qword [esp]` 加两个 NOP，四条 `frndint` 换 NOP。`sub_4520C0` 的调用者只有
`sub_44FE30` 里那两处，改动不外溢。图集是 `A8R8G8B8` 的渐变边，不需要副本。

### th12

同样的两层，但 floor 没有包装函数：`sub_45A570`（签名与 th11 的 `sub_44FE30` 逐字相同）直接调
`_floor`（`0x493290`），左边界 `0x45A6A9`、上边界 `0x45A7AD`，前面都是 `fstp qword [esp]`（`DD 1C 24`），
所以同样换成 `fld qword [esp]` 加两个 NOP。提交侧是 `sub_459E50` 的四条 `frndint`
（`0x459EFA/908/916/924`）。绘制函数先 `call sub_45A570` 算顶点，再 `push 1` 提交，与 th11 一致。

### th20

换了绘制架构。全二进制 9 条 `frndint` 都落在 CRT 或构造函数里（`0x543320` 是 float→int 转换，`0x566E1D`
那一串 `fabs` / `f2xm1` / `ftst` 是 `pow` / `fmod`，`0x483AD0` 带 `___security_cookie` 的初始化器），
2 条 `fsub` 都是 `fsub st,st(n)` 形式，没有减 0.5 常量。

287 条 `cvttss2si` 集中在脚本求值器（`sub_49ABC0` 127 分支、`sub_4408B0`、`sub_4DABA0`、`sub_41E050`）；
四条紧挨的只有 `sub_438620`（状态机写数组）和 `sub_44D9D0`（读 `int16` 宽高做文本），都不碰精灵顶点。

精灵绘制走顶点池：`[this+0x7C00E78]` 是写指针、`[this+0x6000E70]` 是顶点数，`sub_4455C0` 用
`SetFVF(0x144)` 加 `DrawPrimitiveUP(stride 0x1C, TRIANGLELIST)` 提交。`0x144` 是 XYZRHW | DIFFUSE | TEX1，
stride 28 是 4 个 float 坐标加 1 个 dword 色加 2 个 float 贴图。XYZRHW 的 x/y 是浮点，写进池子时没有整数转换。

所以这个作换了架构之后确实不再量化，不需要这一项修复。

## 为什么只有 th07 / th08 需要预乘副本

解包后对比子弹图集的内容与排布（数据在 `IDA逆向\游戏dat资源\<作品>\data`，thtk 拆包）：

| 作品 | 子弹图集 | 格式 | 精灵边缘 alpha 级数 | 中间 alpha 占比 |
|---|---|---|---|---|
| th07 | `etama.png` | `A4R4G4B4` | 16 | 13.5% |
| th08 | `etama.png` | `A4R4G4B4` | 16 | 13.8% |
| th10 | `etama.png` | `A8R8G8B8` | 182 | 33.0% |

三作的精灵都是紧贴排布（`8*8+0+240`、`8*8+8+240`），差别不在间距。th07 / th08 的边缘 alpha 只有 16 级，是一条
硬阶梯，线性过滤越界采到邻居时混出来的东西成了一道看得见的边；th10 的边是 8 位渐变，越界采样落在渐变里，形状
不变，只有颜色轻微偏移。所以 th07 / th08 必须靠预乘副本把越界变成「与透明混合」，th10 不需要。

th11 也查过了，与 th10 逐项一致：`bullet.anm` 的 `etama.png` 是 `A8R8G8B8`、256 个精灵、182 级 alpha、
中间值 33.0%。`th12–th19` 尚未检查。

## 待办

1. th12–th19 的图集格式（`etama.anm` 解包后逐 entry 看 `THTX-Format`）：决定这些作要不要像 th07 / th08
   那样加预乘副本。
2. th12–th19 的子弹是否确实走上面那条 `test ...,1` 的路径（要看子弹管理器的绘制函数分发到哪个入口）。
3. th12–th19 按 th11 的方法复查几何层是否有 `floor` 包装（上表里的「无」是按旧判据得出的）。

## 排查方法

- 取整指令用两条路核对：IDA 里按函数列 `frndint`（`D9 FC`），以及 dumpbin `/DISASM` 独立再数一遍；两边地址一致
  才记进表格。th128 的 `test` 藏在 `test byte ptr [ebp+arg_0], 1` 里，按字节特征会漏，要看指令文本。
- 判断「是否还有第二层取整」的办法：看含 `frndint` 的那个函数的调用者是否调用 CRT 的 `floor`。th10 就是这样
  发现量化其实在几何层；th11–th19 的调用者全都不调 `floor`，所以只需处理 `frndint`。
- 纹理格式用 thtk 拆包后看：`thdat x<版本> <dat>` 拿 anm，`thanm l/x <anm>` 列精灵表并导出 PNG。

## 2026-11-06
```text
自机插帧应该可以预测下一帧位置

以前的方式：正常帧 `A`→插帧 `a`→正常帧 `B`

原本 `a` 处的自机是 `pA+1/2 vA`，其中 `vA` 是 `A` 时刻的自机速度, `pA` 是 `A` 时刻的自机位置

可以在a处直接调用东方正作的按键检测函数，然后判断 `a` 处的按键情况，随后根据该按键情况生成 `va` ，也就是 `a` 时刻的自机速度，于是自机移动就到了 `pA+1/2 va`（但是还是要保证自机不出版面，不然在板边的时候会跳）

这样的话如果在中途停住按键或者启动按键了仍然可以保证流畅性
目前完成补帧的作品都已经实现了这个自机插帧，只对需要新增加补帧的作品进行修改
```
## 2026-10-04

```text
1、需要对应的是子弹、敌人（enm）、直线激光，曲线激光不管它 2、以子弹为例，先找到子弹的链表，然后找到子弹的所有位置更新函数，根据位置更新函数重写一版可回溯的位置更新Update_Undoable(float t)和对应的回溯函数Undo()，其中t为按帧的时间 3、以2倍（在0.5帧处增加一次插值）的插值为例，找到渲染函数Render()，随后：先将所有子弹进行可回溯位置更新Update_Undoable(0.5)（这一步将所有要插值的插掉），再将插值的帧进行渲染Render()，再将子弹位置回溯回去（Undo()）；这其中如果有涉及到随机数的，随机数也要进行保存和回溯 （敌人逻辑应该也不太需要管，没几个子弹是这样的 )
zun（东方正作作者）的渲染和逻辑是分开的，所以只要连续调用渲染函数就能增加帧率 但是为了进行插值，需要将逻辑纳入 但是所有逻辑都整一遍太复杂了，所以我们只考虑子弹和激光的正常移动逻辑 也就是x+=v的逻辑，以及一个变换逻辑  关于变换： 2un为了给子弹更多效果设计了串行或并行的变换，比如： mode8是曲线加速 mode1048576是让子弹变高光 mode2097152是让子弹缓慢加速 等 然后每个子弹都有个逻辑数组存储变换 为了实现效果，需要对这个变换的实现逻辑进行拆解  （不过其实直接插值一个抛物线的速度对多数子弹效果应该也够了
插值抛物线的话 就是单纯的计算这一帧，上一帧，上上帧 的子弹速度，然后插一个抛物线出来 然后计算当前帧的位置值 ，这样一些复杂移动的变换（比如瞬间变向）可能会有问题，但是99%的其它子弹应该都没啥问题
```
